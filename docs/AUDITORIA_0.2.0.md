# Auditoría del flujo local — GALANT v0.2.0

Se revisó el código del checkout `POST` y se ejecutaron pruebas locales. No hubo acceso al VPS Contabo, a su configuración efectiva, logs, backups ni métricas de producción; por ello las conclusiones de infraestructura se limitan al repositorio y a `docker compose config`.

| Etapa | Implementación y evidencia | Hallazgo / límite |
| --- | --- | --- |
| Carga | FastAPI lee en bloques de 1 MiB, limita tamaño, calcula SHA-256 y escribe archivos privados con modo 0600. Registra tiempo y bytes en logs. | La deduplicación distingue el módulo y serializa cargas iguales en PostgreSQL mediante bloqueo transaccional. Dos cargas locales concurrentes produjeron un solo documento; faltan pruebas de carga sostenida y política de retención/antivirus. |
| Validación | PyMuPDF comprueba PDF, cifrado y páginas; Pillow verifica imágenes y tamaño. | El PDF privado de prueba tiene 14 páginas rasterizadas y ninguna capa de texto. La validación no prueba que un documento sea auténtico. |
| Diagnóstico | Cada página registra caracteres nativos, cobertura de imagen, confianza OCR y tiempo. | El diagnóstico de orientación de Tesseract se aplicaba al revés; se corrigió. No hay detección fiable de páginas duplicadas ni perspectiva. |
| Preprocesamiento | Se gira según OSD y se prueba contraste/enfoque solo cuando la primera lectura es débil. | La página 4 del caso privado sigue con confianza baja. No hay benchmark para decidir otros filtros ni corrección de perspectiva. |
| OCR y extracción | PyMuPDF extrae texto nativo; Tesseract lee páginas rasterizadas a 180 DPI. JSON privado conserva texto y todas las palabras con coordenadas, origen, espacio y línea identificable. | 30.019 caracteres y 4.841 palabras en el caso privado. La interpretación tabular por fila e institución sigue pendiente; las coordenadas no equivalen a tablas verificadas. |
| Segunda opinión | RapidOCR local se invoca solo si se configura y la primera lectura es débil; ambas lecturas se conservan sin comparar puntuaciones como probabilidades. | Cuatro páginas ensayadas; pico observado de 893 MB frente a límite de 950 MB del worker. Permanece desactivado hasta disponer de etiquetas y memoria suficiente. |
| Interpretación y verificación | `rules.py` clasifica cotizaciones/F30-1, período y RUT válidos; exige campos de resumen cercanos y se abstiene ante negación, OCR débil o indicios de filas/trabajadores sin asociación. `pipeline.py` mide tiempo de verificación, caché, extracción e interpretación. | El caso privado pasó de tipo desconocido a cotizaciones y período 2026-09. No se extraen aún filas, montos, empleador/trabajador asociados ni estado oficial; las reglas conservadoras no garantizan asociación de filas cuando el OCR pierde la estructura. |
| Persistencia y concurrencia | PostgreSQL guarda cola y resultado; worker serial con reserva transaccional y recuperación de trabajos atascados. Actualiza progreso por página. El JSON se guarda de forma atómica y se valida por estructura, hash, motor e idioma efectivo. | La configuración de prueba usa un worker; no se midieron lotes concurrentes ni restauración tras fallo del servidor. `create_all` no sustituye migraciones. |
| Exportación | Excel usa solo campos estructurados; incluye controles y observaciones. Se mide tiempo de generación y se vuelve a abrir en pruebas. | RUT sin asociación confirmada se indican como tales. Faltan montos y filas porque aún no hay parser validado. |
| Interfaz | React consulta versión al backend, muestra estado y número real de páginas procesadas, evidencia, tiempo y descargas. El listado usa resúmenes y solo consulta evidencia completa del documento seleccionado mientras procesa. | Sondeo del detalle cada 7 s hasta estado terminal; no existen porcentajes de avance. La versión v0.2.0 no está desplegada en el VPS. |

La medición repetible se encuentra en `scripts/benchmark_ocr.py`. En el caso privado, el primer OCR pasó de 112,52 s a 60,96 s y la reinterpretación tomó 0,020 s. El benchmark final midió 162,01 s de CPU total y 188 MB de RAM máxima del proceso Python, sin sumar la memoria simultánea de Tesseract; la CPU total del código inicial no se registró con el mismo arnés. El corpus de aceptación con verdad de referencia, p95, seguridad y backups son trabajos de validación pendientes descritos en `PLAN_PRUEBAS_12_MESES.md`.
